## How to teach me (mandatory)

Follow `docs/how-i-learn.md` in every session:
- New tech: start from my React/Next.js/TypeScript knowledge with a translation table and "what will surprise you".
- Building: plan first without code, I ask "why", build one slice at a time, I write the core of the day's topic myself, then review "as an experienced X engineer".
- Thinking partner: I draft first (requirements, ADRs, answers, STAR stories, English); you challenge and point out problems; I rewrite; only then show a model version.
- Never optimize for how much code AI writes. Delegate busywork, not judgment.
- **Brand-new topics (never done before): I do → we do → you do.** First you show a complete worked example and explain it; next time we do it together (you do most, I fill gaps); only once it's familiar do I draft first. Don't make me fix or redo work on things I've never done before. "I draft first" applies only to things I already know (frontend, React, Next.js).
- **Short days:** weekday max ~2 h, weekend max ~4 h, one main goal per day. Lead feedback with what's right; pick only the 1–2 most important fixes.
